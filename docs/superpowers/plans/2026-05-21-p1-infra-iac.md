# P1 — Infra & IaC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a hardened, Caddy-fronted Docker host on GCP that is also reproducible on Hetzner via a single OpenTofu variable change, with Cloudflare DNS, age-encrypted secrets, and an automated post-deploy smoke test — *without* any Hermes / mitmproxy / Loki yet.

**Architecture:** OpenTofu root module with cloud-selector variable picks between `modules/gcp` and `modules/hetzner`, both consuming a shared cloud-init template. State lives in Hetzner Object Storage (S3-compatible) so it survives `tofu destroy` on the compute side, enabling spin-up/spin-down. Caddy on the VM serves a "200 OK" health page on the public path and 401-walled placeholder paths for `/mitm`, `/graf`, `/hermes` that will be wired to real backends in P2-P5. A separate one-time `infra/bootstrap/` sub-stack provisions the GCP project itself.

**Tech Stack:** OpenTofu ≥1.8, providers `hashicorp/google ~> 5.0`, `hetznercloud/hcloud ~> 1.45`, `cloudflare/cloudflare ~> 4.0`, `hashicorp/cloudinit ~> 2.3`. Caddy 2.x. Docker Compose v2. age for secret encryption. Bash for verify/up/down scripts. Ubuntu 24.04 LTS on both clouds.

## Pre-flight (manual, once) — Task 0

Before the OpenTofu code runs, three external accounts and one domain need to exist. None of these are automated by this plan — they're attested by the verify script later.

**Files:**
- Create: `docs/p1-preflight.md`

- [ ] **Step 0.1: Register a domain**

Use any registrar (Cloudflare Registrar, Namecheap, etc.). The domain doesn't need to host anything else.

- [ ] **Step 0.2: Add the zone to Cloudflare**

In the Cloudflare dashboard: Add Site → enter the domain → choose the Free plan → Cloudflare gives you two nameservers. At your registrar, set NS records to those two nameservers. Wait for Cloudflare to mark the zone "Active" (usually 5-30 minutes; verify with `dig NS <your-domain>` returning Cloudflare's NS records).

- [ ] **Step 0.3: Generate a Cloudflare API token**

Cloudflare dashboard → My Profile → API Tokens → Create Token → "Edit zone DNS" template → restrict to the one zone you just added. Save the token; it goes into `secrets.env` later.

- [ ] **Step 0.4: Have a GCP billing account ID ready**

Console → Billing → copy the billing account ID (looks like `01ABCD-23EFGH-45IJKL`). You need this for the bootstrap stack.

- [ ] **Step 0.5: Have a Hetzner Cloud API token ready**

Hetzner Cloud Console → Project → Security → API Tokens → Generate (Read & Write). Save the token; it goes into `secrets.env`.

- [ ] **Step 0.6: Create a Hetzner Object Storage bucket for OpenTofu state**

Hetzner Cloud Console → Object Storage → Create credential (S3 access key + secret) → create a bucket named `hermes-prototype-tofu-state` in `fsn1` (or your nearest location). This is where ALL OpenTofu state lives, regardless of which cloud the compute is on. Record the endpoint (e.g. `https://fsn1.your-objectstorage.com`), access key, and secret.

- [ ] **Step 0.7: Generate an age keypair**

```bash
brew install age   # macOS; on Linux: apt install age
age-keygen -o ~/.config/hermes-prototype/age.key
chmod 600 ~/.config/hermes-prototype/age.key
# Public key prints during keygen; copy it.
```

The age **private** key stays on your laptop. The age **public** key is committed to the repo as `age.pub`. The bootstrap stack later puts a copy of the private key into GCP Secret Manager / a Hetzner-side equivalent so the VM can decrypt secrets at boot.

- [ ] **Step 0.8: Generate an SSH key for the VM**

```bash
ssh-keygen -t ed25519 -f ~/.ssh/hermes_prototype -C hermes-prototype-vm
```

The public key (`~/.ssh/hermes_prototype.pub`) goes into `.tfvars`. The private key stays on your laptop.

- [ ] **Step 0.9: Document what was done**

Create `docs/p1-preflight.md` recording: domain name (or "TBD"), Cloudflare zone ID, GCP billing account ID, Hetzner project ID, Object Storage bucket name + endpoint, age public key, SSH key path. **This file is gitignored** — it has identifiers but no secrets. Use it as a personal ops crib.

- [ ] **Step 0.10: Commit gitignore update if needed**

```bash
# Verify p1-preflight.md is gitignored — it is via docs/p1-preflight.md pattern
echo "/docs/p1-preflight.md" >> .gitignore
git add .gitignore
git commit -m "chore: gitignore preflight notes"
```

## Task 5: Write the shared cloud-init template

In P1 the cloud-init does the minimum to get a Caddy container running. P4 will add Hermes; P2-P3 will add LGT + mitmproxy. The template is **shared** between the GCP and Hetzner modules.

**Files:**
- Create: `infra/cloud-init/userdata.yaml.tftpl`

- [ ] **Step 5.1: Create `infra/cloud-init/userdata.yaml.tftpl`**

```yaml
#cloud-config
hostname: ${split(".", hostname)[0]}
fqdn: ${hostname}
manage_etc_hosts: true

users:
  - name: hermes
    sudo: ALL=(ALL) NOPASSWD:ALL
    shell: /bin/bash
    groups: [docker]
    ssh_authorized_keys:
      - ${ssh_pubkey}

package_update: true
package_upgrade: true
packages:
  - ca-certificates
  - curl
  - gnupg
  - lsb-release
  - ufw
  - fail2ban
  - git
  - age
  - jq

write_files:
  - path: /etc/ssh/sshd_config.d/90-hermes.conf
    permissions: "0644"
    content: |
      Port ${ssh_port}
      PasswordAuthentication no
      PermitRootLogin no
      X11Forwarding no
      MaxAuthTries 3
  - path: /etc/ufw/applications.d/hermes
    permissions: "0644"
    content: |
      [Hermes-SSH]
      title=SSH on custom port
      description=SSH
      ports=${ssh_port}/tcp
  - path: /etc/hermes/age.recipient
    permissions: "0644"
    content: ${age_recipient}

runcmd:
  # 1. Harden SSH
  - systemctl restart sshd

  # 2. Firewall
  - ufw default deny incoming
  - ufw default allow outgoing
  - ufw allow Hermes-SSH
  - ufw allow 80/tcp
  - ufw allow 443/tcp
  - ufw --force enable

  # 3. Install Docker
  - install -m 0755 -d /etc/apt/keyrings
  - curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
  - chmod a+r /etc/apt/keyrings/docker.asc
  - echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $${VERSION_CODENAME}) stable" > /etc/apt/sources.list.d/docker.list
  - apt-get update
  - apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

  # 4. Clone repo at pinned ref
  - mkdir -p /opt/hermes
  - chown hermes:hermes /opt/hermes
  - sudo -u hermes git clone --branch ${repo_ref} ${repo_url} /opt/hermes

  # 5. Bring up the stack (Caddy only in P1)
  - cd /opt/hermes/stack && docker compose up -d

  # 6. Signal ready
  - touch /var/lib/hermes-bootstrap-complete

final_message: "Hermes prototype host bootstrapped in $UPTIME seconds."
```

## Task 11: Write `scripts/verify.sh` (P1 scope)

In P1 the verify script only checks infra-level concerns. Later plans extend it.

**Files:**
- Create: `scripts/verify.sh`

- [ ] **Step 11.1: Create `scripts/verify.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

HOSTNAME="${1:-}"
SSH_PORT="${SSH_PORT:-2222}"
SSH_TARGET="${SSH_TARGET:-}"

if [[ -z "$HOSTNAME" ]]; then
  echo "usage: $0 <hostname> [SSH_PORT=…] [SSH_TARGET=user@ip]"
  exit 2
fi

fail()  { echo "FAIL: $1"; exit 1; }
pass()  { echo "PASS: $1"; }

# 1. DNS resolves
DNS_IP=$(dig +short "$HOSTNAME" A | head -1)
[[ -n "$DNS_IP" ]] || fail "DNS for $HOSTNAME does not resolve"
pass "DNS for $HOSTNAME -> $DNS_IP"

# 2. TLS valid + Caddy alive
HEALTH=$(curl -sf --max-time 10 "https://$HOSTNAME/health" || true)
[[ "$HEALTH" == "ok" ]] || fail "https://$HOSTNAME/health did not return 'ok' (got: $HEALTH)"
pass "TLS + Caddy serving /health"

# 3. Walled paths return 401 (auth required) — not 5xx
for path in /mitm /graf /hermes; do
  CODE=$(curl -sko /dev/null -w '%{http_code}' --max-time 10 "https://$HOSTNAME$path" || true)
  [[ "$CODE" == "401" ]] || fail "$path returned $CODE (expected 401)"
done
pass "walled paths return 401"

# 4. Containers healthy (over SSH)
if [[ -n "$SSH_TARGET" ]]; then
  STATUS=$(ssh -p "$SSH_PORT" -o StrictHostKeyChecking=accept-new "$SSH_TARGET" \
    "cd /opt/hermes/stack && docker compose ps --format json" || true)
  echo "$STATUS" | jq -r '.[].Health' 2>/dev/null | grep -vq '^healthy$' && \
    fail "at least one container is not healthy" || pass "all containers healthy"
else
  echo "SKIP: container health (no SSH_TARGET provided)"
fi

echo "All P1 checks passed."
```
